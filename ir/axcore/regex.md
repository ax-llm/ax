# ECMAScript schema patterns

`regex.axir` implements the flagless `RegExp(pattern).test(value)` behavior used
by TypeScript's raw tool-argument validator. Session argument validation calls
this shared Core module in Python, Go, Java, C++, and Rust. Host regular-expression
engines remain in use for unrelated existing operations.

The parser and matcher operate on UTF-16 code units, including surrogate pairs.
The only new host operation is `intrinsic.string.utf16_units`; it does not execute
patterns. Applications do not need a JavaScript runtime or another dependency.

## Matching contract

Patterns search the input unless anchored. Supported syntax includes alternatives,
captures, named captures, forward and unmatched backreferences, character classes,
greedy and lazy quantifiers, word boundaries, and positive and negative lookahead
and lookbehind. Flagless legacy escapes follow ECMAScript's Annex B behavior.
Capture names use Unicode 17.0 ID_Start and ID_Continue ranges, with ECMAScript's
additional identifier characters and escaped-name normalization. Duplicate names
are accepted only in disjoint alternatives. Invalid patterns fail validation;
they do not start tool handlers.

The matcher uses an explicit prioritized work stack. Each entry owns a matching
position, capture state, and a linked continuation. Alternatives and quantifiers
push entries in reverse priority order, and matching stops at the first success.
Branches copy captures before modifying them. Quantified subtrees clear their
captures before another iteration. Lookarounds perform an atomic nested search;
lookbehind traverses the expression and input in reverse order. Backreferences
compare captured spans in the current direction. Empty required iterations stop
once the unchanged state satisfies the minimum repetition count.

Iteration count and input length do not consume the language call stack. Nested
patterns and assertions still follow expression depth. As with TypeScript's
backtracking engine, ambiguous failing patterns can require substantial work;
this matcher does not change schema authors' responsibility for pattern cost.

## Evidence and maintenance

`session-ecmascript-pattern-validation.json` is generated by
`tools/axir/extractors/axai-goldens.ts` through the actual TypeScript argument
validator. Its 1,164 cases cover syntax, invalid patterns, Unicode inputs, captures,
lookarounds, legacy escapes, and long successful repetition. Native MCP agent
tests additionally preserve an advanced pattern through provider tool schemas,
reject invalid arguments, execute the valid handler once, and incorporate its
result in the responder.

During implementation, 18,865 deterministic pattern/input comparisons against
Node's RegExp engine also matched the emitted Python Core implementation. The
checked-in TypeScript-derived fixture is the repeatable all-target acceptance
suite. Identifier ranges were derived using Node 26.7.0 (Unicode 17.0); update the
ranges and conformance cases together when changing the supported Unicode version.

Keep matching decisions in this module. In particular, replacing the matcher
with a target's native regular-expression engine loses UTF-16, lookaround, or
backreference behavior on some targets. Keep host collection reads constant-time
for indexed arrays and avoid copying the entire work stack for a map lookup.
